# stoprock firmware

Arduino on ESP32, built with [PlatformIO](https://platformio.org). Behaviour follows [`docs/SPEC.md`](../docs/SPEC.md).

```sh
pio run -e coreink -t upload   # build and flash the M5Stack CoreInk (USB-C)
pio device monitor             # serial console, 115200 baud
pio run -e emu                 # build the simulator image (see ../simulator)
pio test -e native             # logic tests on this computer
pio run -e render && .pio/build/render/program /tmp/r && python3 ../tools/compare_render.py /tmp/r
                               # check the device's screens match the mockups pixel for pixel (main, low battery, help, and the cursor at all 17 positions)
```

## Layout

| Path | What |
|---|---|
| `lib/stoprock_core/` | Timing engine (B2H / H2H state machine), shot log and game databank. Pure C++, no hardware; tested in `test/` |
| `lib/stoprock_ui/` | 1-bit framebuffer and the screens, ported from `tools/mockups/screen.py`. `assets_data.cpp` is generated by `tools/fontgen.py` |
| `src/app.cpp` | The application: buttons, timing, shots, games, sounds, sleep, power and the display task |
| `src/board.h` | Hardware layer, implemented by `board_coreink.cpp` and `board_emu.cpp` (esp-emulator) |
| `src/render_main.cpp` | Host tool that draws the screens to PBM files |
| `partitions.csv` | Flash layout, including the `games` partition for the databank |
| `scripts/merge_bin.py` | Merges the simulator build into one flash image for esp-emulator |

## Serial commands

Type into the serial console:

| Command | Does |
|---|---|
| `t <unix seconds>` | Set the clock, e.g. `t 1795000000` (until the companion app does this) |
| `s` | Status |
| `bank`, `games`, `games new`, `game <id>`, `ack <id>`, `erase-all yes` | Game databank, see [`docs/DATABANK.md`](../docs/DATABANK.md) |
| `audit` | Clock audit: how accurate timing is while the chip sleeps between clicks (see below) |
| `sleeptiming on` / `off` | Sleep between the clicks of a stone (default on) |
| `n` | Start a new game now (switching on also does) |
| `o` | Switch off (shows the help page) |

## After a real game: the clock audit

While a stone is timed the chip sleeps between clicks, and time asleep is counted by a less precise backup
clock. The firmware measures that clock against the real-time clock's crystal throughout the game. After the
game, switch it off as usual (hold the side button 3 s; that takes the audit's final sample). Then plug it into
your Mac, open the serial console (which switches it on, starting a new audit) and type `audit`:

```sh
pio device monitor -e coreink      # then type: audit
```

Each line is one switch-on, the current one first; your game is the line after it (`"current":false`):

```text
@AUDIT
{"current":true,"game":12,"sleep_while_timing":true,"samples":13,"span_s":7210,"slept_s":6980,
 "timer_minus_rtc_ms":-410.0,"sleep_clock_ppm":-59,"results":256,"results_asleep_pct":97.9,
 "est_error_ms_15s_h2h":-0.9}
@END
```

(The numbers above are made up, to show the format.) `est_error_ms_15s_h2h` is what matters: the typical error in
a 15 s H2H caused by sleeping. Under about 3 ms is invisible in hundredths; past about 5 ms, turn sleeping
while timing off with `sleeptiming off`. Send me the output and I'll interpret it.
